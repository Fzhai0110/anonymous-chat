## 1. 项目介绍

**Anonymous Chat 3.0** 是一个基于 Cloudflare Workers 构建的匿名在线聊天平台。

项目旨在提供一个无需注册账号即可参与的公共聊天室，同时支持用户之间的私信、图片分享、消息举报以及管理员管理功能。

与传统聊天平台不同，本项目使用浏览器生成的匿名 ID 识别用户，不要求用户提供邮箱或手机号。

项目后端运行在 Cloudflare Workers 上，使用 Cloudflare D1 保存数据，并结合 Durable Objects 实现实时通信。

### 项目特点

- 无需传统账号注册。
- 支持匿名公共聊天。
- 支持用户之间的私信。
- 支持图片上传。
- 支持消息举报。
- 提供管理员管理后台。
- 支持用户处罚与通知。
- 使用 Cloudflare 基础设施运行。

> 本项目目前仍处于开发和测试阶段，部分功能尚未完成完整验证。

---

## 2. 项目目标

本项目希望实现一个轻量、易部署、具有基本管理能力的匿名聊天系统。

主要目标：

1. 降低用户参与聊天的门槛。
2. 提供稳定的实时消息通信。
3. 尽可能减少不必要的个人信息收集。
4. 提供举报和管理员处理机制。
5. 通过 Cloudflare 服务降低服务器维护成本。
6. 保持代码结构清晰，方便后续维护和扩展。

## 3. 功能特性

### 3.1 公共聊天室

- WebSocket 实时通信。
- 公共消息发送与接收。
- 最近 300 条公共消息历史记录。
- 匿名昵称。
- 消息时间显示。
- 在线连接数统计。

### 3.2 匿名身份系统

- 自动生成匿名用户 ID。
- 使用浏览器 localStorage 保存用户 ID。
- 支持设置和保存昵称。
- 不需要传统账号注册。

注意：匿名 ID 并不是可靠的身份认证机制。

### 3.3 私信系统

- 用户之间发送私信。
- 根据用户 ID 查询相关消息。
- 使用 API 读取私信记录。
- 提供私信数据持久化能力。

当前私信采用 API 读取模型，不代表已经实现完整的实时推送、已读状态和通知系统。

### 3.4 图片系统

- 图片上传至 Cloudflare R2。
- 图片对象持久化保存。
- 后端对上传请求进行检查。
- 支持配置最大图片大小。

图片上传、读取、删除以及消息展示的完整联动，需要根据当前部署版本逐项测试。

### 3.5 举报系统

- 用户可以举报其他用户。
- 可以填写举报理由。
- 举报信息保存到 D1。
- 管理员可以查看举报记录。
- 管理员可以处理举报。
- 处理结果可以通知相关用户。

### 3.6 管理系统

- 管理员身份验证。
- 管理员会话管理。
- 举报管理。
- 用户处罚管理。
- 安全日志。
- 管理员操作审计。

## 12. 用户功能

### 匿名身份

用户第一次访问网站时，前端会生成匿名 ID。

匿名 ID 保存在浏览器 localStorage 中。

清除网站数据后，匿名身份可能丢失。

### 公共聊天

用户可以：

1. 设置昵称。
2. 进入公共聊天室。
3. 发送消息。
4. 接收其他用户的消息。
5. 查看消息时间。
6. 查看在线连接数。

### 私信

用户可以通过私信 API 与其他用户交流。

私信读取必须进行服务端权限检查，不能仅依靠前端隐藏内容。

### 举报

用户可以通过消息旁边的举报入口提交举报理由。

提交成功后，系统应返回相应提示。

## 14. 举报与处罚系统

### 举报流程

```text
用户发现违规行为
        |
        v
    提交举报
        |
        v
    保存到 D1
        |
        v
   管理员查看举报
        |
        v
     处理举报
        |
        v
    记录管理操作
        |
        v
    通知相关用户
```

### 处罚类型

项目数据结构涉及：

- Mute：禁言。
- Ban：用户封禁。
- IP Ban：IP 指纹封禁。

处罚的实际生效范围、到期时间和解除机制必须由服务端执行。

IP 指纹不是用户真实身份，也不能保证准确识别某个具体的人。

IP 级处罚可能影响使用同一网络的其他用户，因此需要谨慎使用。

## 15. 图片系统

项目使用 Cloudflare R2 保存上传图片。

图片上传需要进行服务端验证，包括：

- 文件类型。
- 文件大小。
- 上传权限。
- 请求频率。
- 对象存储访问控制。

不能只相信浏览器提交的 MIME 类型。

图片功能还需要检查：

1. 上传后能否正确保存。
2. 图片地址能否正常访问。
3. 前端能否正确显示图片。
4. 删除操作是否同步处理对象。
5. 举报和图片内容之间是否建立正确关联。

## 16. WebSocket 通信

公共聊天室使用 WebSocket 实现实时通信。

基本流程：

```text
用户打开网站
      |
      v
建立 WebSocket 连接
      |
      v
发送聊天消息
      |
      v
服务器验证消息
      |
      v
广播给聊天室用户
      |
      v
其他用户接收消息
```

需要注意：

- 服务端必须验证消息内容。
- 必须限制消息长度。
- 必须处理断开连接。
- 必须检查用户处罚状态。
- 不应仅依赖前端限制违规操作。

在线连接数不一定等于真实在线人数。

## 18. 安全机制

项目需要关注以下安全问题：

### 输入验证

所有用户输入都必须经过服务端验证。

### 权限验证

管理员接口不能依赖前端权限判断。

### 会话安全

管理员会话需要具备有效期和安全验证。

### 请求限制

聊天、私信、举报和图片上传接口应具备合理的频率限制。

### IP 指纹

使用带盐 SHA-256 指纹处理 IP 相关数据。

不要保存或公开不必要的明文 IP。

### WebSocket 安全

WebSocket 消息同样需要执行权限和处罚检查。

### 数据保护

限制管理员数据和安全日志的访问范围。

## 19. 隐私说明

Anonymous Chat 3.0 使用匿名 ID 提供聊天功能，但匿名不代表完全无法关联访问记录。

用户需要了解：

- 匿名 ID 保存在浏览器本地。
- 聊天消息会被保存。
- 私信不是端到端加密。
- IP 指纹可能属于可关联的在线标识。
- 图片可能保存在对象存储中。
- 管理员可能需要查看举报及相关管理记录。

项目部署者应向用户说明数据用途、保存期限和管理方式。

## 23. 常见问题

### Q1：使用网站需要注册账号吗？

不需要。项目使用浏览器匿名 ID 识别用户。

### Q2：清除浏览器数据会发生什么？

本地匿名 ID 可能丢失，浏览器可能被识别为新的匿名用户。

### Q3：聊天内容是否端到端加密？

当前项目不能被描述为端到端加密聊天系统。

### Q4：为什么在线人数和实际人数可能不同？

当前统计可能基于 WebSocket 连接数，而不是去重后的用户数量。

### Q5：为什么管理员看不到举报？

建议检查：

- 管理员身份验证。
- Worker 日志。
- D1 举报记录。
- 管理员 API 返回结果。
- 前端后台页面的数据加载逻辑。

### Q6：部署失败怎么办？

优先检查：

- wrangler.jsonc。
- package.json。
- D1 数据库绑定。
- Durable Objects 绑定。
